### OWASP 2021: OWASP Top 10:2021  
### PortSwigget Academy:  
- Insecure direct object references (IDOR)  
(IDOR) on eräs pääsynvalvonnan haavoittuvuustyyppi, joka syntyy, kun sovellus käyttää käyttäjän antamaa syötettä kohteiden suoraan käsittelemiseen. Esimerkkinä tästä on tietokantaan kohdistuva IDOR, jossa URL-parametrejen tietoja voidaan muokata ja näin nähdä toisen käyttäjän tietoja.  
/customer_account?customer_number=**132355** = Oma käyttäjä  
/customer_account?customer_number=**132356** = Jonkun toisen käyttäjä  
(Portswigger a)  

- Path traversal
Path traversal hyökkäyksessä verkkosivun tiedostopolun arvoa muutetaan yrittäessä päästä käsiksi palvelimen muihin tiedostoihin.  
Tämän avulla hyökkääjä voi lukea tiedostoja palvelimelta, missä sovellusta suoritetaan.  
(Portswigger b)  
  
- Cross-site scripting
Cross-site skriptaus on verkkosovellusten tietoturva-aukko. Siinä hyökkääjä voi häiritä tai kaapata käyttäjän ja haavoittuvan sovelluksen välistä toimintaa.
Tämä toteutuu, hyökkääjä laittaa haavoittuneen verkkosivun palauttamaan haitallista JavaScriptiä käyttäjälle ja se suoritetaan.  
(Portswigger c)

## Cross Site Scripting (XSS)  
### c) Reflected XSS into HTML context with nothing encoded  

Labran ohjeissa kerrotaan, että sivun hakukentässä on haavoittuvuus ja sen avulla on tulostettava "alert"  

![](Images/H4C1.png)  

<br>

Katsoin melko nopeasti aluksi vastauksen, sillä en saanut hahmotettua, mistä edes aloittaa.  

Ymmärsin ainakin sen, että hakukenttään voidaan sijoittaa koodia pelkän tavallisen tekstin sijasta.  
Hakukentän haavoittuvuuden ansiosta nettisivu ei tulkitse koodinpätkää pelkkänä tekstinä.  

Tässä on vasta GET pyyntö palvelimelle, kun suoritetaan: "<script>alert(1)</script>"  

![](Images/H4Cmaybe.png)  

Mutta mitä palautuu takaisin?  
Tässä nähdään, kuinka skripti osuus ei lueta pelkkänä tekstinä, vaan suoritettavana koodina:  
![](Images/H4C3.png)  

Tein testejä, miltä teksti näyttää HTML:ssä  
erikoismerkit "<>" tulostetaan sellaisenaan ja on juuri se syy, miksi hakukentässä on haavoittuvuus.  

![](Images/H4C4a.png)  
![](Images/H4C4b.png)  

### d) Stored XSS into HTML context with nothing encoded  

Tehtävässä on haavoittuvuus kommenttikentässä. Tarkoitus on luoda kommentti, joka käynnistää "alert" funktion katsoessa blogia.  
![](Images/H4D1.png)  

Nyt tiedän, millä tavalla kutsutaan funktio edellisestä tehtävästä.  
Suuntasin sivun blogeille, jossa eri kenttiä löytyy.  

Tässä on yhden blogin kommenttikenttä.  
Siihen lisätään vain alert skripti ja loput tiedoista täytetään.  
![](Images/H4D2.png)  

Nettisivu kenttä esti kommentin antamisen, mutta sen pystyi jättämään tyhjäksi.  
![](Images/H4D3.png)  

Tämän jälkeen, kun mennään samaan blogiin takaisin, käynnistyy alert(1).  
![](Images/H4D4.png)  

![](Images/H4D5.png)  

Seuraavaksi oli tarkoitus etsiä ZAP:sta, missä näkyy lähetetyt ja palvelimelta vastaanotetut tiedot.  
Tämä koutui erittäin haasteliaaksi.  
Ainoa hyödyllinen asia, mitä sain ZAP:sta oli postID.  
Mutta sitten tämän avulla hain ZAP:sta oikean pyynnön.  
![](Images/H4D6.png)

### g) File path traversal, traversal sequences blocked with absolute path bypass  

Tässä tehtävässä yritetään suorittaa läpikäyntihaavoittuvuus, mutta sivu hylkää hakemistosiirtymät, eli ../../  
Nettisivu silti käsittelee annettua tiedostonimeä suhteessa oletustyöhakemistoon.  
![](Images/H4G1.png)  

Kun ZAP:llä kuunneltiin verkkoliikennettä, nähdään kuinka tiedostoa pyydetään suoraan sen nimellä.  
**/image?filename=**  
Hakemistösiirtymiä ei hyväkstyä, mutta absoluuttisia polkuja ei ohiteta. Juuri kuinka tehtävän nimessä vihjattiin.  
![](Images/H4G2.png)  

Jos lähetetty viesti takaisin toimii, näkymällä "text" näkee itse "passwd" tiedoston tiedot.  
![](Images/H4G3b22.png)  


### h) File path traversal, traversal sequences stripped non-recursively  

Tehtävässä hakemistosiirtymät poistetaan ei-rekursiivisesti, eli vain kerran.
